How did we deploy the system? We implemented the project using two laptops connected through a mobile hotspot. The first laptop hosted the backend API, while the second laptop ran the user interface.

Backend (Laptop 1). We used FastAPI to create the backend and Uvicorn to run the server. The server was started using uvicorn api.main:app --host 0.0.0.0 --port 8000. When the server starts, it loads the final trained model, along with the model configuration and HMM configuration. We implemented three main API endpoints: GET /trips returns the 10 evaluator trip IDs; POST /predict runs the complete prediction pipeline; GET /health checks whether the API is running correctly. The prediction endpoint follows the complete workflow: clean the GPS data, generate road candidates, run LightGBM predictions, apply Viterbi decoding, and reconstruct the final route.

How did we prevent data leakage? An important part of our implementation was ensuring that the reference route was never exposed to the frontend. The .route file is accessed only after the prediction has been completed, inside the evaluate_prediction function. This means the system generates its predictions independently before comparing them with the ground truth.

Frontend (Laptop 2). We created the frontend using a local ui/index.html file and Leaflet. The user can enter the backend API address, click Connect and select a trip. The interface then displays the GPS observations, predicted route, evaluation metrics and execution timings.

Network configuration. Both laptops were connected using a phone hotspot (Laptop 1: 172.20.10.2; Laptop 2: 172.20.10.3). We also enabled CORS to allow communication between the frontend and backend.

Deployment verification. We verified that the two laptops were communicating correctly. Figure 17 shows the user interface running on Laptop 2. Figure 18 shows the backend logs on Laptop 1, confirming requests from 172.20.10.3 with successful HTTP 200 responses. We also verified that Trip 59 produced identical results on both laptops. The complete system processed each trip in approximately 0.2–1.3 seconds.

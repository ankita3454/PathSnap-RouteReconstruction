Why did we introduce an HMM?

The classifier predicts the most likely road for each GPS point independently. However, this creates a problem: even when each prediction looks plausible on its own, consecutive road predictions may not connect properly. For example, the classifier might predict two roads that are geographically close but are not directly connected. To solve this, we introduced a Hidden Markov Model (HMM). It considers both the probability of a road being correct and how well consecutive road predictions connect. We use the Viterbi algorithm to find the most likely sequence of road segments.

Q1. What are the hidden states? For every GPS point, the hidden states represent its candidate roads. Each state contains a road segment along with the position of the GPS point on that road.

Q2. How did we calculate emission probabilities? We used the probabilities generated by LightGBM as emission scores. The emission score is calculated using we × log(normalised LightGBM probability). Here, the probabilities are normalised within each GPS point, and we controls how much importance we give to the classifier's prediction. We also implemented a baseline approach using Gaussian distance-based emissions with a standard deviation of 8 metres. This baseline does not use the classifier.

Q3. How did we calculate transition probabilities? Transition probabilities help us determine whether moving from one candidate road to another makes sense. We compare two distances: the actual driving distance between the roads, and the straight-line distance between consecutive GPS points. We calculate the transition score as −|driving distance − GPS distance| / β. The driving distance is calculated using Dijkstra's shortest-path algorithm, with a maximum search distance of 3 km. If the road network requires a much longer journey than the movement suggested by the GPS points, the transition receives a larger penalty. This helps prevent the model from selecting unrealistic road sequences.

Q4. How did we handle gaps in GPS data? Some GPS points have no available road candidates. Instead of treating these as errors, we simply skip those points during decoding. We also adjust the transition parameter β based on the time difference between consecutive GPS points (β × √Δt). The maximum plausible distance is calculated using 60 m/s × time gap + 50 m. This allows the model to handle missing GPS observations more realistically.

Q5. How did we handle disconnected roads? Sometimes, two consecutive road candidates are not connected in the road network. Instead of assigning an infinite penalty, we use a fixed penalty of −30. This ensures that the Viterbi algorithm can still find a complete sequence. After decoding, any remaining gaps are filled using the shortest available paths.

Decoder tuning. We tuned the HMM parameters using out-of-fold training predictions. We tested 20 trips using a 3 × 3 parameter grid and selected β = 3 and we = 2. These values achieved 93.29% accuracy on the tuning dataset (grid below).

Data preparation: we used the training dataset and student-test dataset for exploratory data analysis. However, all modelling decisions were made using only the training data. The evaluator dataset was kept completely separate and was never used during model development.

2.1 Q1. What preprocessing steps did we perform?

We followed several preprocessing steps before training the model.

1. Data cleaning. We removed missing values, invalid coordinates, duplicate timestamps and other out-of-range observations. We also sorted all GPS points chronologically. Interestingly, we found zero invalid rows in the dataset.

2. Coordinate projection. We converted GPS coordinates into a local metric coordinate system for each trip. This was necessary because latitude and longitude do not represent equal physical distances everywhere. For example, our trips covered latitudes from -34° to 62°. At the latitude of Trip 11, one degree of longitude represents approximately 62 km, whereas one degree of latitude represents approximately 111 km. Using a suitable projection allowed us to calculate distances more accurately.

3. Road network cropping. To reduce unnecessary computation, we cropped the road network using the GPS bounding box and added an 800-metre buffer. This ensured that all the roads belonging to the reference routes were retained. We successfully preserved 100% of the route roads.

4. Creating labels. Since the reference route did not directly provide labels for individual GPS points, we needed to generate them. We used a monotonic dynamic-programming alignment method to match GPS points with the roads in the reference route. This was important because simply assigning the nearest road can produce incorrect labels. For example, in Trip 11, naive nearest-road snapping produced incorrect results for 43% of the GPS points. All these errors involved reverse-direction road twins.

5. Removing problematic trips. We excluded Trips 33 and 54 because their median GPS offsets were unusually high (Trip 33: 122 metres; Trip 54: 140 metres). After removing these trips, we had 78 training trips available.

6. Candidate generation. We used a KD-tree to efficiently search for nearby road candidates. Road samples were generated every 10 metres, and for each GPS point, we selected candidates within a 50-metre radius, with a maximum of 8 candidates (K = 8). The resulting candidate miss rate was 1.85% on training and 0.42% on test. We also experimented with increasing the radius to 80 metres and K to 12. Although this reduced the miss rate slightly, it increased the number of rows by 52% while providing less than one percentage point of improvement.
